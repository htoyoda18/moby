- replyLoop
  - UDP プロキシのバックエンドからの返信をクライアントに転送する役割を持つゴルーチンとして動作するメソッド
  - 処理の詳細
    - クリーンアップ処理
    - OOB(Out-of-Band)データの準備
      - 送信元 IP アドレスを制御メッセージとして設定
    - メインループ
      - 読み取りタイムアウトの設定
      - エラーハンドリング
      - データ転送
        - WriteMsgUDP を使用して OOB データとともにクライアントに転送
- Run
  - 概要
    - UDP プロキシのメインループで、クライアント → バックエンドの方向のトラフィックを転送
    - 受信したパケットごとに適切な接続を選択/作成し、バックエンドに転送する「トラフィックの振り分け役」
  - 処理の詳細
    - 初期設定
      - 受信バッファを確保
      - 宛先 IP アドレスを取得するための制御メッセージを準備
    - メインループ
      - クライアントからのパケット受信
      - コネクショントラッキング
        - クライアントのアドレスをキーにして接続を管理
        - 初回パケット時:
          - バックエンドへの新しい接続を作成 & replyLoop を起動
        - 2 回目以降:
          - 既存の接続を再利用
      - バックエンドへ転送
  - Run のユースケース
    1. Docker コンテナ起動時にポートマッピング
    2. userland proxy が有効の場合
    3. docker-proxy プロセスが別プロセスとして起動
    4. そのプロセスの main 関数から Run() が呼ばれる
    5. Run() はブロッキング動作し、プロキシがシャットダウンされるまで戻らない
